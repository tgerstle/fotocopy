# Phase 7: Local Execution & Production Deployment (Overview)

## Objective

Before fully speccing out and deploying to Cloudflare and Postgres, our immediate goal is to prove the pipeline end-to-end locally. We will spin up a local instance of Payload CMS 3.0 (with SQLite) to ensure our Next.js frontend perfectly reads the machine-generated CMS blueprints. Once local execution is flawless, we will expand this phase to cover OpenNext and Cloudflare edge deployments.

## Core Concepts

### 1. Local Payload CMS Seeding (Immediate Focus)

- We move beyond the local JSON file reads used in Phase 0.
- **Script:** A headless Payload Initialization script connects to a local SQLite database.
- **Action:** It reads the `/output/*.json` files (generated by the Phase 3 Hydrator) and uses `payload.create()` to bulk insert pages and collections natively.

### 2. Cloudflare R2 Asset Syncing (Deferred)

- During Phase 1, all legacy `<img src>` tags were downloaded locally to `/migrated-media/` for offline testing.
- **Script:** An R2 Sync script bulk-uploads these assets to a Cloudflare Bucket.
- **Replacement:** The CMS Seeder rewrites the image URLs in the Payload blocks from `http://localhost/migrated-media/x.jpg` to `https://cdn.fotocopy.com/x.jpg`.

### 3. OpenNext Cloudflare Deployment (Deferred)

- Configuring Next.js to compile seamlessly into Cloudflare Workers/Pages using `@opennextjs/cloudflare`.
- Setting up the Edge caching rules so the Payload CMS backend serves lightning-fast to the frontend.

## Impact on Tracer Bullet (Phase 0)

- The Tracer Bullet `p0_04` is currently rendering direct from a JSON file. Phase 0 can be updated to seed a local SQLite instance of Payload just to prove the DB injection schema perfectly handles the mock data before we test with actual crawled data.
